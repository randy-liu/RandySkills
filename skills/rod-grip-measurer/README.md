# Rod Grip Measurer

由官方商品圖量出釣竿的**握把長度**與**可利用竿長**。

**這個 skill 是備案，不是首選。** 原廠規格表如果有グリップ長，就用官方值（🟢），
不要用這裡量出來的 🟡 值去取代它。

---

## 為什麼需要它

`rod-curve-generator` 的彎曲模型需要知道「從竿尾算起哪一段不會彎」。
持竿時的固定端是**手**，不是竿尾——輪座＋握把那一整段不參與彎曲。

模型原本把全長整段都當成有錐度的竿身在算，等於用一根過長的槓桿去達成同樣的竿尖下沉量，
結果是**彎得太靠元端**。補上這一段之後，12 支竿的竿尖角跨距從 25.3° 收斂到 17.7°，
而且與唯一一份實物受力照片的量測偏差**補掉了約一半**（見
`rod-curve-generator/references/ccs_calibration.md` §10）。

問題是：**DAIWA Heartland 的規格欄沒有グリップ長**（欄位只有全長／継数／仕舞寸法／自重／
先径・元径／ルアー／ライン／カーボン含有率），而且該系列 12 款全是センターカット，
仕舞/全長 都是 0.52，**也無法用「全長 − 仕舞」反推**。

---

## 方法：圖裡自帶一把尺

官方商品圖多數是**拆成兩節平放**——而**元節的像素長度就對應官方公佈的仕舞寸法**。
這就是整個方法能成立的原因：不需要知道相機參數，圖裡已經有一個已知長度。

1. 逐列統計暗像素，切出水平帶（每一帶＝一節）。
2. 厚度最大的那一帶是**元節**（有握把）。
3. **比例尺** ＝ 元節像素長 ÷ 仕舞寸法。（整支組裝的圖則用總長 ÷ 全長。）
4. 沿元節找「厚度 ≥ 0.6×最大值、**且連續超過 1.2% 節長**」的最外緣 ＝ **前握把前緣**。
5. `握把 = 竿尾端 → 前握把前緣`；`可利用竿長 = 全長 − 握把`。
6. 輸出複驗圖，紅線畫在偵測到的前緣。

厚度用 **half-max**（背景與該行最暗值的中點），不是固定門檻——不同商品圖的曝光與壓縮
程度不同，固定門檻在深色圖上會把竿身量胖。

## 🔴 三道防線，每一道都是被咬過才加的

### ① 「連續」條件——導環會騙你

第一版的握把前緣判定只要求「厚度 ≥ 0.6×最大值」，沒有連續長度的條件。
結果 `722MLRSS-24` 被量成 **96.5cm**（真值 34.5cm）——被最大導環的**單點厚度尖峰**騙了。

導環很短、握把很長，所以「必須連續超過節長的 1.2%」就能把導環濾掉而不影響握把。
**這個條件不可省。**

### ② 合理性檢查——不合理就不輸出

握把佔全長必須落在 **10〜25%**（實測 12 支落在 12.8〜18.7%）。超出範圍時**量測直接失敗、
不輸出任何數值**，要求人工檢視複驗圖。

這比下游 `rod-curve-generator` 的 30% 護欄更嚴——**生產端就該擋掉，
不要讓壞資料走到只剩最後一道防線**。

### ③ 寫入後自我複查——文件會長大

`--write` 寫進量測表之後，會**自己再讀一次**確認：讀回來的真的是握把欄、筆數對、
值落在 15〜60cm。任何一項不對就**自動回滾**。

這一道的由來：`measured_grip_lengths.md` 後來加了第二張同形狀的表（可利用竿長，
第 4 欄是 177.8 而不是握把 30.2），下游的解析器照欄位序讀，**第二張把第一張整個覆蓋掉**——
12 張圖全部畫錯，過程中**一個錯誤訊息都沒有**，是靠逐像素比對舊圖才發現的。

→ 教訓：**文件是會長大的，寫入端不能假設「這個檔案裡剛好只有一張表」。**

## 🔴 人工把關點：複驗圖

腳本一定會輸出 `<型號>_grip_check.png`。**必須實際開圖看過。**

這是唯一能抓到下列錯誤的一步——這幾種錯誤都會產生「看起來很合理」的數字：

- 抓錯帶（把竿尖節當成元節）
- 圖其實是整支組裝好的，卻被當成拆節圖（比例尺差一倍）
- 紅線落在後握把前緣而不是前握把前緣

**數字合理不等於位置抓對。**

## 交叉檢查：`⊘ 無法檢查` 不是通過

| 檢查 | 對照 |
|---|---|
| 竿尖最細處 | 官方先径 |
| 握把前緣上方的裸竿身 | 官方元径 |
| EVA 握把最粗 | 18〜32mm |
| 兩節像素和 − 全長 ＝ 接管重疊 | 應為正值、約 5〜8cm |

低解析圖（約 9 px/cm）的 1.6mm 竿尖只有 **1.3px**，偵測不到——先径與接管重疊兩項會變成
`⊘ 無法檢查`。那是**竿尖節的偵測極限，不影響元節與握把長度**（元節最細處也有 9mm），
但也**不能拿來當作量對了的證據**。

`722MLRSS-24` 的 4000px 圖四項全過，可以當成方法本身成立的示範：

| 檢查 | 量到 | 對照 | |
|---|---|---|---|
| 竿尖最細處 | 1.13 mm | 官方先径 1.6 mm | ✅ |
| 握把前緣上方的裸竿身 | 9.63 mm | 官方元径 9.4 mm | ✅ |
| EVA 握把最粗 | 24.07 mm | 常識 18〜32mm | ✅ |
| 接管重疊 | 7.12 cm | V-JOINT 對接的合理值 | ✅ |

## 🔴 嚴禁用公式回填

量不出來就是量不出來。**不得用「這個長度的竿大概幾公分」補上去。**

實測 12 支中，**同樣是 218cm 的六支，握把從 30.1 到 40.8cm——同長度內就差 10.7cm**。
最好的規則（紡車／貝爾各自對全長做線性）RMS 仍有 1.94cm、最大誤差 3.26cm，
等於把大部分資訊丟掉。這是逐支資料，不是規則。

下游對「沒有量測值」已有正確處理：警告、圖上標「未量測」、不套用握把剛性。
**那是正確行為，不是為了讓圖畫得出來而該去補的缺陷。**

## 回歸測試

```bash
uv run scripts/validate_grips.py                 # 連網，抓官方圖
uv run scripts/validate_grips.py --image-dir DIR # 離線，用本機圖
```

12 支答案卷在 `references/reference_photos.md`。誤差須 < 1.0cm 且圖型判定一致。
目前 **12/12 通過，最大誤差 0.04cm**。

抓不到圖標 `SKIP` 並在結尾列出——**跳過不計為通過**，全部跳過則失敗。
官網換圖時回產品頁重抓網址更新答案卷，**不要放寬門檻**。

## 依賴需求

`numpy`、`pillow`，以 PEP 723 內聯宣告，用 `uv run` 執行。
⚠️ `uv` 屬外部相依，不隨本 repo 安裝。

複驗圖的中文標題需要系統上有中文字型（Windows 的 msjh/msyh/simhei、macOS 的 PingFang、
Linux 的 Noto CJK）。找不到時會**自動退回英文標題**——
🔴 不會硬畫中文，因為 PIL 預設字型畫出來是整排豆腐字，圖上的字看不懂等於沒有字。
