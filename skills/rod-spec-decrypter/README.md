# Rod Spec Decrypter

從釣竿的**物理幾何與材質資料**反推真實手感、感度與定位，繞開官方型錄的行銷修辭。

**這個 skill 的核心賣點不是「答得多」，是「分得清哪些是查到的、哪些是推的、哪些不知道」。**
任何讓可信度標示變模糊的改動，都是在拆掉它唯一的價值。

---

## 為什麼要有它

型錄會說「粘りのあるブランク」「操作性が飛躍的に向上」——那些是文案，不是規格。
但同一張規格表上的**先径／元径／全長／継数／仕舞寸法／適合ライン／カーボン含有率**是客觀數字，
型號字串裡還藏著原廠自己標的調性。

→ 所以：**只吃客觀欄位，推演一律自己算，結論逐項標可信度。**

## 三本字典，各管各的（這個分工是硬規則）

| 檔案 | 回答什麼 | 載入時機 |
|---|---|---|
| `references/daiwa_technology.md` | **技術是什麼意思**（物理影響、動態手感） | 必載 |
| `references/daiwa_model_naming.md` | **型號字串怎麼拆**（命名文法） | 必載 |
| `references/daiwa_heartland_features.md` | **這一支竿是什麼**（搭載技術、官方數值、官方文案） | 僅當 prompt 指名該系列 |

🔴 **技術字典不記載搭載機種**，所以**不能反查「字典裡有 X，所以這支竿應該有 X」**。
某支竿有哪些技術，一律由使用者輸入／官方文案／產品特性檔提供。

🔴 **命名字典裡的型號只是解析驗證基準**（錨定文法的最小樣本），**不是可供比較的竿款清單**。

🔴 **嚴禁憑記憶拆型號或解釋技術。** 命名規則是廠牌專屬的——各廠的長度編碼、力量字母、
後綴含義都不一樣，憑印象拆會產生跨廠誤用。字典查不到就照實說「不在字典庫中，需要更新 Skill」。

## 🔴 措辭精確度：三件事不可混為一談

這是本 skill 最常被踩的地方，也是使用者實際糾正過最多次的地方：

| 說法 | 意思 |
|---|---|
| 「**官方規格表沒有這一欄**」 | 規格表的欄位清單裡沒有它 |
| 「**資料在別處**」 | 規格表沒列，但技術頁／產品頁／實體吊牌／零售商規格欄有 |
| 「**查無此資料**」 | 上面幾層都查過了，真的沒有 |

**典型案例：導環圈材質。** 官方規格表確實沒這一欄——但原廠技術頁與各機種產品頁有導環系統說明，
實體吊牌上更直接印著規格。所以它的正確狀態是「**尚未查證**」，不是「查不到」。

→ 依序查：產品特性檔 → 官方網站 → 非官方規格頁（🟡，須註明出處）→ 才標未知，
　並且**說明卡在上面哪一層**。

🔴 **嚴禁**從外觀照片、價格帶、系列定位推測。
🔴 **嚴禁**把「規格表沒這一欄」寫成「原廠沒有公佈」。

## 兩支腳本：它們算什麼、以及它們不算什麼

### `scripts/calculate_taper.py` — 幾何錐度

`元徑 ÷ 先徑`，分成 EX-Fast（≥10.0）／Fast（≥7.5）／Regular（≥7.0）／Slow。

**但兩點式錐度比有已知的失效情況**，所以腳本另有兩項進階診斷：

| 診斷 | 門檻 | 抓什麼 |
|---|---|---|
| 元端過剩指數 | ≥ 100 | 屁股相對於設計負載過度強壯 → 元端根本不參與作動 |
| 全體纖細 | 元徑 < 8.5mm | 兩端絕對尺寸都極小 → 高比值失真 |

🔴 **只要有全長與負載上限就必須帶 `--length` 與 `--max-lure`。** 省略等同關掉安全網。

⚠️ **這兩個門檻是由 12 支 DAIWA HEARTLAND 實測樣本歸納的暫定值**，樣本數不足以視為定論。
它們只用來**提醒人工複核**，**不得據以推翻官方標示的調性**。

⚠️ 腳本**不負責**抓「材質造成的調性落差」（例如 X45／3DX 提升響應速度，
讓胴調子幾何被官方標成 `F`）。那是 Step 2 的職責，不要期待腳本示警。

### `scripts/calculate_sensitivity.py` — 感度鏈路

🔴 **它一律不輸出分數、不評分、不排名。**

理由寫在腳本檔頭：調性判定敢下結論，是因為型號字串裡就有原廠標的調性可以對答案；
**感度沒有這種東西**——官方規格表沒有感度欄位，也沒有任何可對答案的公佈值。
**任何感度分數都是捏造的。**

它只輸出兩樣不需要對答案就能成立的東西：①訊號鏈上哪一環有問題　②每個數字代表什麼。

門檻：接繼偏心指數 `1.15`（🟡 幾何推導，非實測，亦無官方依據）、
物理下限 `0.98`、負載跨度 `5.0` 倍。

### 🔴 兩支腳本共有的一個陷阱：Windows 主控台編碼

兩支都在檔頭強制把 stdout/stderr 切成 UTF-8。**不要拿掉。**

Windows 預設 cp950 編不出 `³`／`≈`／`％`，會拋 `UnicodeEncodeError`——
而**崩潰點在主要判定印出「之後」**：外觀上像正常跑完，實際上進階診斷或該區塊的判讀**整段消失**，
極易被誤判成「這支竿沒有觸發診斷」。

## 感度：三個通道，可推導性天差地遠

「感度」在物理上是三件不同的事，報告裡不得混為一談：

| 通道 | 白話 | 能推到什麼程度 |
|---|---|---|
| 荷重感度 | 感覺得到餌的重量、底質從沙變泥 | **可推**（純幾何） |
| 敲擊感度 | 餌撞到石頭那一下 | 部分可推 |
| 質感感度 | 分辨得出碎石還是水草 | **幾乎推不了**，須照實說推不了 |

訊號鏈是**串聯**：`餌 → 線 → 竿先 → 導環 → blank → 接繼 → 輪座 → 手`。
**串聯系統的傳導上限由最差的一環決定**，所以結論取最差那一環，不是加總或平均。
（也因此不給總分——總分會把爛掉的那一環稀釋掉。）

⚠️ **報告裡不准把這五樣簡稱為「五環」。** 「環」在釣竿上是**導環**的名字，
拿零件名去指代整條鏈，讀者會直接誤解。

### 兩條硬規則

1. **任一環節「未知」且可能比目前已知最差的還差時，不得下定論。**
   必須寫「瓶頸可能在＿＿，但因為缺＿＿的資料，無法確定」，不得挑一個已知環節交差。
2. **「不適用」不是「未知」。**
   1 節竿的「接繼」是不適用（無接繼）——那是已知事實而且是有利條件，
   標成「未知」會誤觸規則 1，把好消息寫成資料缺口。

⚠️ **握把材質不得單獨卡住結論**：感覺咬訊時手握在**輪座**上，那才是最後一道介面。

## 報告寫給誰看

**目標讀者設定為國中生**——沒摸過釣竿、沒學過材料力學，但看得懂數字與比喻。

分析本身維持無情工程師視角。**白話化只作用於「怎麼講」，不作用於「講什麼」**：
不得為了好讀而簡化推演、跳過矛盾或美化不確定性。

幾條反覆被違反的：

- 🔴 **嚴禁自創「◯◯字母」這類代稱。** 型號裡的 `F`／`R`／`S` 就是原廠標的調性本身。
  「一個名詞如果本身還需要一句解釋才看得懂，代表它不該存在。」
- 🔴 **不要畫 ASCII 圖，一張都不要。** 文字＋比喻已足以讓國中生看懂（實測結論，不是偏好）。
  想畫圖的衝動代表**文字還沒講清楚**，回去把文字寫好。
  唯一例外是單行流程標記（`餌 → 線 → 竿先 → …`），那是符號記法不是圖。
- **反直覺的物理原理必須配日常比喻**——一句話寫完的原理，看得懂的人本來就已經懂了，等於沒寫。
- **每個數字後面緊接一句「這代表什麼」**，不要只丟 `Ratio 5.88，判定胴調子`。
- 🔴 **白話化不得稀釋可信度標示。** 白話版必須**更直白，不是更含糊**：
  「這是原廠自己寫的」／「原廠沒明講，這是我推的」／「我不知道，也不會猜」。

## 與其他 skill 的介面

**輸出檔名固定為 `<型號>_分析報告.md`。**
🔴 `rod-curve-generator` 靠這個檔名找報告，改檔名它就找不到。
它會從報告解析**全長／先径・元径／ルアー重量**（缺一就無法產圖）。

🔴 **產圖前，報告 §2-3「綜合手感預測」必須與腳本的兩條警示一致。**
曲線引擎用的是**與 `calculate_taper.py` 相同的門檻**（元徑 < 8.5mm、元端過剩指數 ≥ 100）
去調整彎曲分佈。文字結論若與警示相左，**先修報告**——否則同一支竿會有兩套互相矛盾的說法。

⚠️ **分析完不要自己接著產圖。** 三個理由：粒度不同（對比圖需要整批報告完成）、
相依不同（產圖要 numpy／matplotlib，本 skill 不需要）、
守則邊界（守則 3 禁止報告之間交叉比較，而對比圖正是跨竿比較——
兩者相容的前提是每份報告都已各自獨立完成）。

技術搭載清單由 `rod-tech-splitter` 產出並寫進 features 檔；
握把長度由 `rod-grip-measurer` 量測，但那是給曲線引擎用的，本 skill 不使用。

## 依賴需求

`scripts/` 底下兩支腳本只用標準函式庫，**不需要 numpy／matplotlib**。
未安裝 Python 不影響 skill 安裝，但分析時將取不到幾何判定結果。
