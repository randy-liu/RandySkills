# Rod Curve Generator

這個 Skill 把釣竿的幾何參數丟進大撓度懸臂梁解算器，畫出受力時的彎曲曲線圖。

**曲線的「形狀」有答案卷可以對，「撓曲的公分數」沒有。** 這是本 skill 最重要的一句話，先講在前面：

| | 校準狀態 | 能怎麼用 |
|---|---|---|
| **彎在哪裡**（形狀、調性） | ✅ 對照 21 支公佈 CCS 實測值，RMS 4.5° | 可以說「這支比那支彎得更靠前」 |
| **彎多少公分**（絕對撓曲量） | ⚠️ 平均對得上，但**逐支散佈 ×/÷ 1.47** | **不可以**說「掛 5g 會沉 20 公分」 |

詳見 [`references/ccs_calibration.md`](references/ccs_calibration.md)。

### 🔴 還有第三件事：圖畫的是「形狀」，不是「反應」

這是**靜態掛重**的圖。而釣竿的手感有一半是動態的——依技術字典，`3DX` 買到的是「形狀復原力、回彈極快」、`X45` 買到的是「防止扭轉變形」，**兩者都不改變靜態掛重時的形狀**。

→ 所以搭載這類技術的竿，**實際手感會比圖上「更快」**，那個差額是靜態曲線在物理上就畫不出來的。
→ 圖上已印有固定聲明；**在對話中講圖時也必須一併講明**，否則讀者會把「圖上比較慢」讀成「這支竿比較慢」，那是兩個不同的主張。

**這條界線也是一條繪圖規則**：原廠調性字母若與幾何矛盾、且該落差**可歸因於純動態技術**，就不拿它決定起彎點，改依幾何。
裁判是技術字典，不是印象。已知案例：`6102MLFS-19` 幾何是胴調（比值 6.60）、原廠標 `F`，而官方文案自己寫明那個 `F` 來自 X45＋3DX → **靜態曲線依幾何畫**。

⚠️ **「無法解釋」不等於「可歸因」，只有後者有資格推翻原廠標示。** 反例：`772ML+FS-22` 同樣是 `F` 對上胴調幾何，但查遍它身上每一項技術都沒有把它往快拉的——落差**無法解釋**，所以依守則以原廠標示為準，圖照樣畫 `F`，並在報告中標明這是全報告最沒把握的一段。

## 核心功能

本工具內建雙模產圖系統，提供兩種截然不同的分析視角：

1. **ZENAQ 風格圖表 (`plot-zenaq`)**
   - **45度角持竿模擬**：模擬實戰中將釣竿上舉 45 度角的受力曲線。
   - **動態負載計算**：自動讀取釣竿的 `Lure_Rating`（路亞克數），推演出最適合的測試重量區間。
   - **無干涉儀表板排版**：採用左右分離的 Dashboard 佈局，將「數據繪圖區」與「文字資訊區」進行物理隔離，確保硬調竿在輕負載下也絕對不會與文字重疊。
   - **產出內容**：包含所有釣竿的同重量對比圖（Comparison），以及單把釣竿的多負載漸進圖（Progressive）。

2. **工程分析版圖表 (`plot-engineering`)**
   - **水平極限測試**：從 0 度角（水平）出發，模擬極端環境下的受力彎曲。
   - **與 45 度圖同一組負載**：兩張圖吃的是同一個依額定推演的動態階梯（額定下限的 0.8 倍起跳、等比分到上限、加一個 1.15 倍的超額點、再加固定 100g 的搏魚點），差別**只在持竿角度**。
   - **專業工程方塊**：在畫面左下方附上超詳細的規格表（長度、先徑、元徑、路亞負載等），如同官方出廠的規格文件。

## 輸入來源

吃的是 `rod-spec-decrypter` 產出的 `<型號>_分析報告.md`。**檔名是兩個 skill 之間的契約**——`extract` 只認 `*_分析報告.md`。

## 使用方式

本工具已針對 AI 進行指令封裝 (`SKILL.md`)，直接吩咐 AI：
> 「幫我把 `RodAction` 資料夾裡面的釣竿，用 `rod-curve-generator` 畫出 ZENAQ 圖跟工程圖」

AI 會執行三個標準步驟：
1. **資料萃取 (`extract`)**：從各份報告抓取規格。缺少**全長／先径・元径／ルアー重量**任一項的報告會被跳出、列為失敗，並以 exit code 1 結束，AI 必須停下來請使用者補齊。
2. **自動計算與繪圖 (`plot-zenaq` / `plot-engineering`)**：透過隔離的 Python 環境 (`uv run`) 進行物理運算，不弄髒全域環境。
3. **歸檔輸出**：逐支圖進 `Progressive_Curves/`、`Engineering_Curves/` 兩個子目錄，**跨竿對比圖則放在 `--output-dir` 那一層**。

⚠️ 兩個 plot 指令都會在 `--output-dir` 底下**自己再開一層同名子目錄**。要圖落在 `X/Progressive_Curves/` 就傳 `--output-dir X`，不是 `--output-dir X/Progressive_Curves`。

## 改動曲線引擎時

柔度定律的常數彼此綁定，動一個會牽動其他。改完必須跑回歸測試：

```bash
python <skill_dir>/scripts/validate_ccs.py
```

它拿引擎去考 21 支已公佈 CCS Action Angle 的空白竿身，三道門檻：**量法自我驗證**（等剛度懸臂梁須算出 ≈28.6°）、**RMS ≤ 5°**、**模型跨距 ≥ 實測跨距的 55%**，外加 `k_power` 階梯表的**單調性檢查**。

🔴 **跨距與單調性這兩道不是多餘的**，它們抓的是 RMS 看不到的失效：

- 改版前的引擎相關係數有 +0.538 看似不差，但跨距只有 1.6°（實測 14.0°）——它把每支竿都畫成同一個形狀，只是平均而言錯得一致。
- `k_power` 只改變「彎多少」不改變「彎在哪」，所以它出錯時形狀分數完全正常。曾經有兩格不單調（額定 11g 的竿被畫得比 10g 還軟），角度測試一點反應都沒有。

🔴 **改了 `derive_curve_parameters()`（起彎點／`k_power`／乘數）必須重跑 `extract`，不能只重畫。** 那些值是在 `extract` 階段算好寫進 JSON 的，`plot` 只是讀檔——只重畫的話圖不會變，而且圖上 `[Model Parameters]` 還會印舊值，看起來像修改沒生效。

## 🔴 圖上不會出現沒查證過的東西

這些圖會被拿去跟官方型錄對照，所以腳本**不替任何欄位填預設值**：

- 解析不到的欄位一律顯示「報告未提供」，不會顯示成看起來像規格的數字。
- **材質與抗扭技術只在報告載明時才印**。（早期版本把 `HVF NANOPLUS` 與 `X45` 寫死在程式裡，導致每一張圖都宣稱同一組技術——已移除。）
- **原廠調性四碼 `S`／`R`／`F`／`X` 原樣保留**，報告沒寫就標「報告未提供」，不會替它填一個。
- 圖上 `[Model Parameters]` 區塊已標明是**繪圖用推估值，非原廠數據**。
- 廠牌與系列名不寫死在標題裡——腳本無從得知進來的是哪個系列。

## 🔴 校準本身的限制，也照實講

- **柔度指數 `1/d⁴` 是實測擬合出來的有效指數，不是物理推導。** 有個好聽的推導是「壁厚正比於直徑，所以 `I ∝ d⁴`」——**那個推導已被否證**（由公佈自重反推壁厚，`t/d` 與元徑的相關係數是 −0.765）。不得在任何地方把它寫成物理事實。
- **整套校準只有一個來源、一個廠牌**（Batson/Rainshadow 21 支空白竿身）。這不是選擇，是限制——其他來源都缺一角：有彎曲資料的不出幾何，出幾何的沒有彎曲資料。
- **跨廠適用性未驗證，且各常數風險不一。** 純幾何／結構的部分（指數）會跨廠；翻譯行銷標籤的部分（`Fast` → 剖面、額定重量 → 剛度）不會。21 支裡 18 支標 `Fast`，所以「F 與 R 之間差多少」基本上是外推的。
- **幾何解釋不了的下限約 ±4°**：兩支錐度比幾乎相同的竿（8.30／8.28）實測差 5.5°，差在碳布疊層與模數分佈，無人公佈。→ 校準目標是**消除系統性偏差**，不是逐支吻合；追求逐支吻合等於擬合雜訊。

## 依賴需求
底層腳本採用 PEP 723 內聯中繼資料宣告依賴 (`numpy`, `matplotlib`)，由 `uv` 自動管理，無需手動安裝套件。
⚠️ `uv` 本身屬外部相依（science plugin 的 `uv` skill），不隨本 repo 安裝。
