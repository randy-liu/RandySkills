# Rod Tech Splitter

把官方產品頁上**整個系列共用**的技術清單，還原成**每一支竿各自的搭載明細**。

**產出是「機種級事實」——哪一支竿有什麼技術。** 不解釋技術是什麼，也不做手感分析。

---

## 為什麼要有它

廠牌官方頁的技術區塊（如 DAIWA 的「ダイワテクノロジー」）是**整個系列共用**的：
一份清單列出所有技術，再用小字 `※` 標註哪些只適用於部分型號。

所以「這個系列有 X45」是頁面層級的事實，「**這一支竿**有沒有 X45」要另外拆。
拆錯的後果會一路傳下去——`rod-spec-decrypter` 會拿錯誤的技術清單去推手感。

---

## 職責邊界

| 問題 | 由誰回答 |
|---|---|
| 這支竿有哪些技術 | **本 Skill** |
| 該技術的物理影響是什麼 | `rod-spec-decrypter/references/<廠牌>_technology.md` |
| 這支竿拿起來什麼手感 | `rod-spec-decrypter` |

🔴 **嚴禁解釋技術的物理影響。** 技術說明欄位一律**濃縮自官方原文**，
不得加入自己的物理推論、手感描述或調性判斷。

🔴 **嚴禁補上官方沒寫的技術。** 「這個等級的竿應該有 XX」是腦補。官方清單沒列就是沒有。

🔴 **產出寫進 `rod-spec-decrypter/references/<廠牌>_<系列>_features.md`，
嚴禁寫入 `<廠牌>_technology.md`**——該檔明文禁止登錄任何型號、系列名或搭載清單。

## 拆分規則

### Step 0：先固定型號全集

從「製品スペック」表或頁面型號清單抓出該頁**所有**型號。

🔴 **這是後續所有判定的分母，必須先列示給使用者確認。**
全集錯了，「無標註 ＝ 全部」的每一條都會錯。

⚠️ **缺型號全集就停止。** 不得用技術區塊裡 `※` 提到的型號拼湊全集——
那只涵蓋「有標註」的技術，湊出來的分母是殘缺的。

### Step 1：標註規則

| 標註 | 語意 | 歸屬 |
|---|---|---|
| **無 `※`** | 系列通用 | 全集所有型號 |
| `※ A、Bのみ` | 限定 | 僅 A、B |
| `※ A除く` | 排除 | 全集扣除 A |

🔴 **型號採精準比對。** 官方頁常混用全形／半形（`７０２ＵＬ＋ＦＳ－ＳＴ２３` vs `702UL+FS-ST23`）
與 `＋`／`+`，**必須正規化後再比對**；正規化後仍對不上就停止並回報，不得猜測。

### Step 2：衝突消解

兩項技術同時落在同一支竿、且物理上不可能並存時——**先分部位，衝突只在同部位成立**：

| 部位 | 例 |
|---|---|
| 竿身補強層 | X45、X45フルシールド、3DX |
| 竿身碳布 | HVF NANOPLUS、SVF COMPILE-X |
| 竿先 | MEGA TOP、SMT |
| 接繼 | V-JOINT、V-JOINTα、へら合わせ |
| 握把／輪座 | AIR SENSOR SEAT |

- **規則 A**：同部位互斥時，**有 `※` 標註者優先於無標註者**。特定標註是原廠對該型號的明確指定，
  通用項只是系列預設值。被擠掉的通用項記為「非搭載」並註明原因。
- **規則 B**：**跨部位不算衝突，一律並存**。實心竿先接管狀本體是常見做法，
  兩者描述的不是同一段竿身。判定並存但字面看似矛盾的組合，須加 `※` 註記說明部位分工並列出佐證。

### Step 3：三重交叉驗證

拆分結果必須與三個**獨立來源**對照，**全部對得上才算完成**：

1. **各竿的官方介紹文**——文中點名的技術有沒有出現在結果裡？
2. **型號字串後綴**（如 `ST` ↔ 實心竿先技術）——拆解規則查命名字典，**不得憑記憶**。
3. **規格數值**——如實心竿先通常明顯細於同系列空心竿。

🔴 **對不上時停止並回報矛盾，不得自行選一邊。**
例如介紹文點名了某技術、但 `※` 標註把該竿排除——那是資料源本身的衝突，必須交由使用者裁決。

## 🔴 可信度：三層來源，兩個方向都會出錯

| 層 | 來源 | 分級 |
|---|---|---|
| ① | 官方技術清單的 `※` 標註（原廠點名機種） | 🟢 |
| ② | **該機種「紹介」文直接寫出技術名稱** | 🟢 |
| ③ | 「無標註 ＝ 全部」的規則推論 | 🟡 |

**第 ② 層最容易被漏掉而誤降為 🟡**——原廠明明寫在該機種頁面上，卻被說成「這是我推的」。
那是**低報證據強度**。標可信度之前，務必先把該竿的紹介文掃過一遍。

反過來把第 ③ 層寫成 🟢 則是**虛報**。
🔴 **「無標註 ＝ 全部搭載」本身是規則推論，不是原廠逐款聲明**，寫入 features 檔時必須標 🟡。

**兩個方向都會讓可信度標示失去意義。**

⚠️ 但只有寫出**技術名稱本身**才算第 ② 層。
「細身肉厚のチューブラーブランク」是**描述**，不等於寫出了 `TUBULAR POWER SLIM`——
不嚴格區分，這一層會蔓延到行銷修辭上。

## 適用範圍

**已驗證：DAIWA 日本官網（daiwa.com）的系列產品頁。**

⚠️ **其他廠牌（Shimano、Major Craft 等）未驗證。** 各廠標註文法不同——
未必使用 `※`、未必用「のみ／除く」。遇到非 DAIWA 來源時**先向使用者說明本 skill 的標註規則
只在 DAIWA 頁面上驗證過**，請對方確認該頁的標註語意後再執行，**不得直接套用硬解**。

輸入需為該頁轉成的 markdown／純文字，且**必須同時包含**技術區塊與型號全集。
缺技術區塊、只有各竿介紹文時可執行，但必須標示
「本結果僅涵蓋介紹文提及者，未經技術清單交叉驗證，可能不完整」。

---

## 依賴需求

無腳本、無外部相依。純規則執行，全部寫在 `SKILL.md` 裡。
